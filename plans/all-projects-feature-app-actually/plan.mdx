<Section id="why" title="Why">

Every route in `src/app/app.routes.server.ts` is `RenderMode.Client`. The SSR
server never renders the component tree, so `curl /thoughts/signals` returns an
empty `<app-root>` shell. The Thoughts pages carry the app's only shareable,
indexable content, and today it is invisible to bots. That is SSR configured to
do nothing.

This is the enterprise proof: **per-route render modes**. Prerender (SSG) the
content routes that need SEO and fast first paint; keep the heavyweight
interactive desktop client-rendered. One app, two rendering strategies, chosen
per route — exactly what Angular's render modes exist for.

</Section>

<Section id="render-modes" title="Render modes (app.routes.server.ts)">

| Route | Before | After | Why | Detail |
|---|---|---|---|---|
| `thoughts` | Client | **Prerender** | List is static, SEO-relevant | Emitted as `dist/.../browser/thoughts/index.html` at build |
| `thoughts/:slug` | Client | **Prerender + getPrerenderParams** | Each entry is known at build time | `getPrerenderParams()` returns `THOUGHTS.map(t => ({ slug: t.slug }))` — one HTML file per thought |
| `**` (root/desktop) | Client | Client | Interactive OS shell, not SEO surface | Hybrid strategy — deliberately client-rendered |

</Section>

<Section id="seo" title="SeoService — src/app/shared/seo.service.ts (new)">

Reuses Angular's `Title` and `Meta` (from `@angular/platform-browser`) and the
injected `DOCUMENT`. A normal `providedIn: 'root'` service, like the other
services in `shared/`.

| Method | Sets | Detail |
|---|---|---|
| `setThoughtMeta(thought)` | title, description, keywords, og:*, twitter:*, canonical, JSON-LD | `<title>{title} — Paul Sumido</title>`, `og:type=article`, canonical + `og:url` = `${SITE_ORIGIN}/thoughts/${slug}`, JSON-LD `BlogPosting` with headline/description/datePublished/author |
| `setListMeta()` | title, description, og:*, canonical | `og:type=website`; removes any stale JSON-LD |

Wired into `ThoughtDetailComponent` (calls `setThoughtMeta` when the thought
resolves) and `ThoughtsListComponent` (calls `setListMeta`). `SITE_ORIGIN` is an
exported constant — a config value to point at the production domain.

</Section>

<Section id="hydration" title="Hydration correctness">

The shell now renders on the server for the first time, so time-varying UI must
not break hydration.

| Change | File | Why |
|---|---|---|
| Guard clock `setInterval` with `isPlatformBrowser` | `menu-bar/menu-bar.ts` | The interval must never start on the server |
| `ngSkipHydration` on the menu bar | `menu-bar/menu-bar.ts` host | Server-rendered clock time ≠ client bootstrap time; a deliberate hydration boundary rather than a mismatch |

</Section>

`thoughts-content/thoughts-data.ts`.

</Section>

<Section id="risks" title="Risks">

- Server now renders the full shell — browser-only APIs must be guarded (clock interval handled; `@defer` blocks render as placeholders server-side; no windows open on fresh render).
- Hydration mismatch on time-varying UI — handled with `ngSkipHydration` on the menu bar.
